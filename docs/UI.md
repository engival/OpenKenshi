# Client UI layer (client/src/ui/)

Brief and decisions: `docs/CLIENT.md` "UI layer". Owner kenshi-10 (branch `ui`, worktree `~/git/kenshi/kenshi-ui`); main.cpp hooks are wired by kenshi-0f.
Options live in `config.hpp` (one kclient.cfg); the UI's own: `ui.scale`.

## Assets (all read from the player's install at run time, never shipped)

- One texture, `data/gui/gfx/Kenshi_UI.png` (1920x1080). All 92 skins and the image sets point into it.
- Skins: `data/gui/skins/kenshi_skins.xml`, `common_skins.xml`. MyGUI `ResourceSkin`: `size`, `BasisSkin type="SubSkin"` children with a widget-local `offset` + `align`, `State name="normal|highlighted|pushed|disabled|*_checked" offset="ax ay w h"` (atlas rect); `SimpleText` children carry per-state text colours. A 9-slice is nine SubSkins; edges stretch (no tiling). Many skins have only `normal`.
- Image sets: `data/gui/images/kenshi_images.xml` (36; icons such as `Kenshi_CharacterSpeedSet`).
- Fonts: `data/gui/fonts/kenshi_fonts.xml` -> TTF in the same folder (Exo2-SemiBold for Standard/Floater, Sentencia_1 for PaintedText (buttons), MailartRubberstamp for banners). Size in points at `Resolution 50`. Licences: Exo2 is OFL; Sentencia_1 "All Rights Reserved", MailartRubberstamp unconfirmed: read from the install, never bundle.
- Colours: `data/gui/colours/kenshi_colours.xml` (Main #afa68b, Secondary #140806, Good, BadBright, Special, item grades).
- Layouts: `data/gui/layout/*.layout` (52) are a reference only.
- Item icons (`icons.*`, loose PNGs outside the atlas): the game's icon cache `data/icons/<item sid>.<material sid>.png` (1,211 here; the game renders it itself for records with `auto icon image`, so an item never shown on this machine has none; some names carry a third id, e.g. `...686-gamedata.base.54583-rebirth.mod.png`, meaning not yet read), else the record's `icon` file field (`.\data\items\icons\basic_medkit.png` -> `icons::recordPath`). 64 px per cell (a 2 x 8 limb is 128 x 512). Item footprint: `inventory footprint width / height` (ITEM, WEAPON, ARMOUR, CONTAINER); a backpack's grid: CONTAINER `storage size width / height` (Small Backpack 8 x 8, Large 12 x 20). Robotics figure: `gui/gfx/figure.png`.

## Architecture

All in the `kui` static library (client/CMakeLists.txt); the host supplies the sokol, stb_image and stb_truetype implementations and `config.cpp`.

- `xml.*`: a minimal XML reader (elements, attributes, BOM, comments) for the MyGUI files. Own code.
- `gfx.*`: the one atlas texture; fill / frame / sprite / tiled / textured quads; nested scissor clips. **No sokol in ui/** (render hook 8, kenshi-k16.2.205.12.38; design `kenshi-inspect findings/kenshi-k16.2.205.12.28/DESIGN.md`): the primitives record into a `dl::List` (`client/src/render/drawlist.hpp`) between `gfx::begin(list, w, h)` / `gfx::end`; `ui::record(list)` is one frame of the UI. The render side applies the list's uploads and replays it (`dl::gpu::apply` / `replay`), making the sgl calls the UI used to make (the alpha-blend pipeline and the linear / trilinear samplers live in `dl::gpu`), so the pictures are bit for bit the same. Textures are `dl::TexId`s: the atlas (`gfx::atlas()`), font pages and icons are made on the CPU and recorded as uploads on `gfx::uploads()` (the list being recorded, else a pending list the next `begin` takes: text is measured and pages baked during layout too); a re-baked page is a new id and the old one's destroy. Host textures (portraits, prospecting map, title art, the animation view) are ids the host binds render side (`dl::gpu::bind`); `PortraitRef` / `TextureImage` / `HudMember::portrait` carry only the id. `gfx::host(rect, fn)` copies `fn` into the list: it runs at the replay, so it captures by value. Transitional shim until the host records into its frame packet: `ui::draw()` and `gfx::begin(w, h)` / `end()` record into gfx's own list and replay it at `end` on the spot.
- `style.*`: **Styles** (user direction 2026-10-31: layouts are ours and will change, so prefab game art cannot be the base). Widgets and screens name a role (`ui::Look`: window, panel, HUD panel, inset, field, input, button, toggle, tick, slot, portrait, bar fill / stun / hurt, slider track / thumb / arrows, speech, menu, tooltip, world tag, pause / speed 1-3); the active `ui::Style` draws it, says its natural size, text area and text colour, and answers named colours (`res::colour` goes through it). `ui.style` (choice, next start): `flat` (default) = our own drawing (fills, 1-unit borders, gradients, an accent; glyphs for pause / speed; a light for toggles), palette in `ui.colour.<Name>` options (#rrggbb or #rrggbbaa; Window, Panel, Inset, Border, Button, ButtonHover, Accent, Main, Secondary, Title, Special, Good, Bad, BadBright, BarFill, BarStun, BarHurt, ItemGrade0-4, ItemArtifact; other names fall back to kenshi_colours.xml) on their own Options tab with a swatch; panels and bars follow edits live, text colours set by screens at the next start. `original` = the game's skins per role (Kenshi_GenericWindowSkin, Kenshi_LifeBarSkin, ...; roles without one, e.g. the world tag, draw flat). Only stretchable pieces are used, never prefab frames (the old HealthPanelTop with 9 painted slots is gone). Host: `ui::drawTag(rect, text, TagState{kNormal, kHover, kFriendly, kStealing, kOwned}, font, ink)` between `gfx::begin` / `gfx::end` for world labels. kStealing: hovered and theft (red frame, red text); kOwned: someone else's, not hovered (the red frame twice as thick on the normal background, `ink` as passed; the original with ALT, user 2026-11-05). Item labels follow kinspect `findings/picker.md` (Kenshi_ItemDropLabel). `ink` is the text colour while not hovered: the host picks `ItemStandard` (#e0cccc), `ItemArtifact`, or `ItemGrade0..4` by level (<16, <36, <51, <66, ≤80; above that, ItemArtifact). The game's colour file has no ItemGrade5. `kStealing` is the hover look with the frame and text in `DropLabelSteal` #ff6666, the game's DropItemLabel*SelectedStealing pair. The host side: the " (N)" count, the 707-unit and on-screen filter, clamping, and overlap push-up. **Themes**: `ui::init(dataDir, themes)` takes mod folders whose gui/ files replace the game's, per file, last wins (`res::setRoots`; `res::file("gfx/Kenshi_UI.png")` resolves a path the same way, for host-loaded art). The Dark UI mod ships colours, gfx (atlas, figure, loading screen), skins, templates and layouts but no fonts; under `original` it gives dark skins, and under `flat` its atlas images and colour file. The host passes the enabled `mod.darkui` folder. kui_demo: `--theme "<install>/mods/Dark UI"`.
- `skin.*` (`ui::res`): skins, image sets (atlas groups only), named colours. `Skin::draw(rect, scale, state, checked)` places each part by MyGUI's align rules (a part keeps its distance to the edges it is aligned to; stretched parts take the rest), edges rounded to whole pixels. Missing states fall back to the unchecked twin, then normal. Disabled text: the skins say black; we dim the normal colour instead.
- `font.*`: TTF from kenshi_fonts.xml, packed with stb_truetype (32-126, 160-255, 8192-8303), re-baked when the pixel size changes. **Size rule (2026-11-01, measured):** MyGUI's: `Size` is points at `Resolution` dpi (default 96), so pixels = Size × dpi / 72 at 1080 lines and scale 100 (Kenshi_PaintedTextFont_Medium 25 at 50 dpi = 17.4 px; the in-game Dark UI caption measures exactly that, cap height 14). **That number is the em** (kenshi-k16.3.33): MyGUI hands it to FreeType as the char size and its line ("real height") is the ascent and the descent, each rounded up; the game scales the em with the screen height (its MyGUI.log at 1440 lines: FloaterFont Small / Medium / Large 23 / 25 / 30, StandardFont_Medium 23, PaintedTextFont_Medium 25 = em x 1440 / 1080, exactly; 12 / 13 / 16 for the FloaterFonts at 720). We bake with stb's em mapping (`STBTT_POINT_SIZE`, em kept to 1/64 px) and that line rule. stb's plain font_size is the ascent-to-descent height (1.2 em for Exo2), which made every Exo2 font 0.83 of the game's: FloaterFont_Small at 720 lines a 9 px line, read as "no pixels" in k16.2.275.1. That read is retired (kenshi-k16.3.34): `client/retired/font_ascent_descent_size.cpp`. The earlier rule (Size as pixels, dpi ignored) made all text 1.44× too big, the main reason our screens looked off. Body text is Kenshi_StandardFont_Medium (13.9 px, the game's stats / tooltip text); Small (9.7 px) only for item counts, MediumSmall for the dense HUD. UTF-8, invalid bytes read as Latin-1. No kerning, on purpose: MyGUI's TrueType fonts advance by glyph only (no kern pairs), so kerning would make our text differ from the original's.
- `widget.*`: the retained tree. Geometry in units (1 unit = 1 px on a 1080-line screen at ui.scale 100), laid out to pixels every frame. Placement: `rect.x/y` is the distance from the aligned edge (`halign`/`valign` = start / end / center / stretch; stretched: `rect.w/h` is the far margin). `preferred()` sizes fitted widgets (Label, Button, Box, Panel with a zero side). Kinds: Panel (skin, padding, fits children), Label (wrap, align, shadow), Image (atlas rect or image set entry), Button (skin states, text, icon, checkable, onClicked / onDoubleClicked / onToggle / onOtherClick), TickBox, Box (row / column), Tabs (a header-only tab bar, the screen shows the page in onSelect: `kTop` a strip of fitted text tabs, `Look::kTabTop`, the selected one in ButtonTextOn over a 2-unit accent underline, a hairline under the strip; wider than its rect, < > arrows (kScrollLeft / Right) at its right end and the wheel step the first tab shown, and select() brings a hidden tab into view; `kLeft` a list in a ScrollView, full-width rows `Look::kTabSide` (a 3-unit accent bar on the selected one, text from the left), `heading()` group labels in Accent, a hairline on its right; a click on the selected tab does nothing; original style: Kenshi_Button1Skin), Flex (row / column sharing its length: each child a `FlexItem{basis, fill, min, max}`; fixed or preferred children first, then fill weights share the rest, clamped with re-sharing (CSS flex-grow); the cross axis by the child's align, kStretch filling; `justify` places them when none fills; preferred() is the least it needs; lays out into the rect it is given, reads no screen size (OpenXR)), ScrollView (wheel; the bar's 6-unit column drags the thumb, a click above / below pages; while it shows the content keeps 14 units clear (column + an 8-unit gap); stickToEnd), List (wrapped selectable rows, numbered + keys 1-9: dialogue choices), TextLog, Menu (popup; held mode picks on release; Item.title = a centred header row with a rule, never picked; `pickable(i)`; `keepOnMiss`: a held release on no pickable row (a disabled row, the title, outside) leaves it open for a click instead of closing, ItemMenu's), Dropdown (a Button, `Look::kInput`, the pick or its placeholder dimmed, a drawn arrow; a click opens a Menu of `items` under it, at least as wide; a pick sets `selected` then calls `onPick`), EditBox (one line, `Look::kInput`; kenshi-k16.3.18: a selection between `anchor_` and the caret, drawn as a `TextSelect` fill behind the text while focused; Shift + Left / Right / Home / End extend it, a plain arrow collapses it to its near end, Ctrl + Left / Right (and Ctrl + Backspace) a word, Shift + click and a drag extend from the press, a double click and Ctrl+A select all; typing, paste, Backspace and Delete replace it; Ctrl+C / X / V via the host's clipboard functions (`ui::setClipboardFns(get, set)` fills the static `clipboardGet` / `clipboardSet`; none set: no clipboard; ui/ calls no sapp clipboard function, render hook 3, kenshi-k16.3.29; kclient sets sapp's and `enable_clipboard`, kui_demo sapp's and its test's own; a paste stops at a line break and is refused past `maxBytes`); the keypad: X11 reports KP_n whatever NumLock, and a char only with NumLock on (needs sokol `up/numlock-keypad`, kenshi-k16.3.38.1: upstream's X11 keysym table also maps the NumLock-off keysyms XK_KP_Home..XK_KP_Insert to digits, so keypad Home typed '7'), so a keypad key-down navigates (KP_4 / 6 left / right, KP_7 / 1 Home / End, KP_DECIMAL Delete, the rest nothing) and a digit / '.' / ',' char in the same frame puts the state back and types it instead; KP_ENTER is Enter; `selected()`, `select(from, to)`, `caret()` for tests; kui_demo frame 11 checks each binding), Toasts.
- `diamond.*`: `ui::Diamond`, a diamond button: a square turned 45° over its rect, arrow tabs at the tips of one axis (`vertical`: up / down, else left / right), a centred `text` and / or a `picture(px, ink)` callback; `active` (a mode it stands for is on) draws the rim in Accent, 7 units wide (5 off), the face washed with it. Each half is its own button (`onStep(-1 first / +1 second)`, `firstEnabled` / `secondEnabled`, `firstTip` / `secondTip`); the hit area is the diamond, so two may overlap like tiles. Our own drawing in both styles, palette Edge / Border / Window, tabs Button / ButtonHover / ButtonDown, arrows ButtonText*, ink Main (deferred: the game's skin in `original` once kinspect names it).
- `ui.*`: the context. Layers overlay (toasts, zone banner, message box: drawn first, at the HUD's level, so every window covers them), root, popups, tooltip on top (0.5 s hover, wrapped, kept on screen). scale = framebuffer height / 1080 x `ui.scale` %; the framebuffer size comes from the host, `ui::setViewport(w, h)` each frame before `ui::frame` (ui/ calls no sapp size function: render hook 2, kenshi-k16.3.29; none set: one log line, laid out at zero size). Routing: the UI sees every event first; `event()` returns true when it used it. Presses and wheel over a solid widget are consumed, as are releases of a press the UI captured and keys the focused widget handles; mouse moves are never consumed (use `wantsMouse()` before world hover-picking). A press outside an open popup only closes it. Click = press + release on the same widget; double click within 0.35 s. Widgets may destroy themselves (or anything) in callbacks: `detail::forget` clears the context's pointers.
- Sounds (kenshi-k16.3.17; kinspect `findings/audio_sfx_triggers.md` sections 2, 3, 5): `ui::setSoundSink(fn(SoundPost{event, group, value}))` from the host; widgets and screens call `ui::sound(event, group, value)` with the original's Wwise event name and at most one switch, which the host sets on the GUI object (110) before the post; the host hashes the names.
